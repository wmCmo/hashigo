# src/blobs — the store that owns the bytes. Content-addressed by sha256, refcounted by the schema, and deliberately holding NO location: the database stores `blobs.hash`, the payload lives in a store, and the store is a runtime argument. Move, rename or re-mount it and every reference still resolves — `src/blobs/cli.ts --store <elsewhere.db> audit` is how you check. The production backing is `sqlite.ts` (BLOB rows in a separate `<db>.blobs.db`, ONE implementation used in Node and in the browser, because per-file OPFS writes measured tens of times slower (32×–65× to write, 20×–95× to read, across the runs that measured both halves) — `notes/archive/browser-feasibility.md` §4); `node.ts` is the directory store, kept for export, interop and the relocation proof; `address.ts`, `store.ts`, `sha256.ts` and `db.ts` are pure and the OPFS build imports them unchanged; `db.ts` audits, resolves and sweeps.

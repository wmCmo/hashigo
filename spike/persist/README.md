# `spike/persist/` — THROWAWAY

**Every file in this directory is disposable harness.** It exists to settle the
one question that can lose Zach's data — *will the browser keep it?* — and it is
safe to delete once the PWA shell exists. Nothing in `src/` imports it.

The findings are in [`notes/persistence.md`](../../notes/persistence.md). The
checklist Zach runs on his own phone is [`PHONE-TEST.md`](../../PHONE-TEST.md).

```
spike/persist/
  index.html               the page, styled for a phone in one hand
  main.ts                  main thread: persist(), the risk banner, Web Locks, tabs
  db.worker.ts             the Worker: all SQLite; steps A-H
  protocol.ts              the messages between them
  env.d.ts                 vite/client ambient types so this slice typechecks alone
  tsconfig.json            `npx tsc -p spike/persist` -> exit 0
  drive.mjs                CDP driver: real Chrome, no automation dependency
  make-icons.mjs           generates icon-192.png / icon-512.png (PWA install)
  manifest.webmanifest     makes /persist/ installable
  sw.js                    a service worker that caches NOTHING, for installability
  icon-192.png             GENERATED by make-icons.mjs, not authored
  icon-512.png             GENERATED by make-icons.mjs, not authored
```

## Run it

The page lives on the **dev server only**, at `/persist/`. `vite build` emits
just `spike/index.html`, because adding a second `build.rollupOptions.input`
means editing `vite.config.ts`, which this change does not own. See the ORPHAN
note in `notes/persistence.md`.

```bash
npm run spike:bootstrap                    # once; build/spike/hashigo-bootstrap.db
node spike/persist/make-icons.mjs          # once; the two PNGs
npm run spike:dev                          # http://localhost:5273/persist/
npx tsc -p spike/persist                   # exit 0
```

Driven, in real Chrome 151, one fresh profile per scenario:

```bash
node spike/persist/drive.mjs deny       # persist() with no permission  (the default)
node spike/persist/drive.mjs grant      # persist() with durableStorage granted
node spike/persist/drive.mjs fill       # write ~700 MB; quota before/after
node spike/persist/drive.mjs quota      # a 400 MiB quota, overrun on purpose
node spike/persist/drive.mjs starve     # start up ALREADY over quota
node spike/persist/drive.mjs multitab   # two tabs, one sahpool
node spike/persist/drive.mjs handles    # does close() release the OPFS file?
node spike/persist/drive.mjs evict      # real eviction + timed recovery
```

Useful flags: `--show` (a visible window), `--port <cdp port>`,
`--url <page>`, `--quota <bytes>`, `--insecure-origin <origin>` (mirrors
Android's `chrome://flags/#unsafely-treat-insecure-origin-as-secure`).

## Why raw CDP instead of Playwright

Two things this spike needs are not exposed by any automation wrapper, and both
are load-bearing:

* `Browser.grantPermissions(["durableStorage"])` — the only way to observe the
  `persist() === true` branch on a desktop. Without it the granted path is
  untestable and its plumbing unproven.
* `Storage.overrideQuotaForOrigin` — lets the page be driven **into** the quota
  in seconds instead of writing 10 GiB to Zach's disk.

Node 24 has a global `WebSocket`, so CDP is 90 lines and zero dependencies.

## Safety

`drive.mjs` uses a fresh `--user-data-dir` under the OS temp directory per run
and deletes it afterwards, so no scenario can inherit another's OPFS or
permissions, and none of them touches Zach's real Chrome profile. The only file
this harness writes inside the repo is the two generated PNGs.
